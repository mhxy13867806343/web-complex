## xiaohongshu/ —— 修复上拉加载（本轮，commit 2848fe7 已推送）

用户截图问「上拉加载 呢？？？」——瀑布流只渲染 4 张、滚到底不触发加载。

### 根因（重要，已验证）
- **NutUI `InfiniteLoading` 的 `target` 必须是元素 id（传给 `document.getElementById(target)`），不能是 CSS 选择器。**
  传 `target=".page-body"` 时 `getElementById('.page-body')` 返回 null → 静默回退到 `window`；
  而真正的滚动容器是 `.page-body`（overflow-y:auto），`window` 根本不滚动 → `onLoadMore` 永远不触发。
  （源码：`node_modules/@nutui/nutui-react/dist/es/packages/infiniteloading/infiniteloading.js` 第 59 行）
- ⚠️ **更正上面「交互补齐」段那句 `target=".page-body"`**：应为 `target="page-body"`（id，不带 #）。

## 本环境启动长进程的经验（重要，省下次时间）
- **`rm -rf <dir>` 会触发沙箱「安全删除保护」钩子**（SAFE_DELETE_BULK_CONFIRM_REQUIRED，阈值 50 个/回合），
  批量递归删除被拦、整条命令直接失败。→ 启动 dev server 前**不要 `rm -rf node_modules/.vite`**，直接 `npm run dev` 即可（vite 自己处理缓存）。
- **`nohup ... &` + `disown` 不行**：工具调用返回时整个进程组被沙箱回收，子进程秒死。
- **`run_in_background:true` 是正确方式**（harness 托管后台任务），但实测**跨回合会被回收**（首个 dev 任务跑 2m6s 后 failed）。
  → 当前回合内稳定可用；若用户下一回合发现打不开，重新说「启动服务」即可。
- 固定端口更省心：`npm run dev -- --port 5188 --host`（避免 5173 被别的项目占、自动顺延导致地址飘）。
- 本机可直连 localhost（清了 .vite 后 `curl localhost:5188` 通），无需再怀疑沙箱网络隔离。
